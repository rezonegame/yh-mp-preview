# 3.21.0-beta.3 微信引用输出适配候选

用户明确确认 beta.2 更新并重新粘贴后，深度阅读在微信手机仍出现灰色左封口。beta.2 的具体边框声明只证明本地样式稳定，没有解决这次真实反馈。手机图中的右边与代码块／正文基本对齐，不能继续断言当前仍贴屏幕；主要未解决证据是左竖线。

## 改动范围

只对带升级版阅读标记的最终复制／导出克隆，将 blockquote 转为带 role=note、aria-label=引用 的 section，完整移动原有子节点、样式和引用来源属性。Markdown、本地 blockquote DOM、转换前的 ArticleModel 引用统计不变；嵌套、强调、步骤和末尾保留。配方先应用，转换后仍经过同一安全清理、文本规范化和验证流程。无升级标记的旧修订／自定义主题输出不变。

深度阅读仍显示上下横线、无左右边框；其他升级主题保留自身侧线／浅底／框线设计。复制 HTML、HTML 导出和图片导出快照共用同一转换，手机预览选项不改变输出宽度。没有额外修改字体、主题、原文、笔记增强或设置。

机制是基于用户反馈和公开 [doocs/md #447](https://github.com/doocs/md/issues/447) 的推断：微信新编辑器可能把原生引用转换为自己的样式。没有访问此账号远端 DOM，也没有复制上游实现；模拟 CSS 不是微信真实规则。普通容器是否在实际后台稳定仍须验收。

真实系统剪贴板往返、后台粘贴／保存和手机结果仍由用户验收。用户手机图显示的较粗正文尚未独立诊断，本补丁不声称解决全部视觉差异。早前 beta.1 的官方数字扫描不覆盖此代码，不能用于此次稳定晋级。来源审计与历史许可保留，静态精确无匹配不等同于独立来源认证。
