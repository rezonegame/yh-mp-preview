# 公众号主题与切换体验完整升级方案

日期：2026-10-02。起点：3.19.1。状态更新：2026-10-03，P0/P1 已验收；P2 的 beta.3 已由用户完整验收，稳定 3.21.0 已发布并同步官方网站，全部 13 资产核验通过。隔离原生安装器安装通过，自动目录更新检测未发现候选，二者单独记录。P3/P4 未实施。实际证据见 [执行记录](THEME_EXPERIENCE_EXECUTION.md)。

研究依据见 [第二轮研究与证据](THEME_EXPERIENCE_RESEARCH_2026-10-02.md)。本文件是下一轮**公众号主题体验**的执行计划，不替代此前笔记增强计划，不重新启动已完成的全盘重构。

## 1. 最终效果与不可改变的边界

作者打开画廊，在同一篇文章上比较同场景的两个版式；确认后直接使用。需要时在该版式内选择少量配色和阅读密度。画廊仍工整、轻量，正文预览仍是主角，最后仍由作者点击 Pub 复制。

必须保留：

- 7 场景 × 2 个精选版式、现有名称与 ID；卡片只显示名字及选中标识；推荐用途放在选中后的底部。
- 小按钮进入历史主题；5 个历史 ID 继续存在，自定义主题和隐藏但正在使用的主题仍可解析。
- 3.19.1 按面板实际宽高适配的工作台、专注预览、折叠完整检查、全部复制与导出入口。
- 用户字号、字体、背景和配方选择；字体／字号仍为现有全局设置，不因换主题自动改变。
- 编辑模式中的当前文章文本、图片、顺序和手工内容。不得为了预览重读 Markdown 而丢掉仅在预览中做的文本编辑。
- Obsidian 笔记增强的三套笔记主题、存储和编辑边界；公众号同名 ID 的变更不得影响笔记主题。
- 仓库 `rezonegame/yh-mp-preview`、插件 ID `yh-mp-preview`、现有合法来源记录和 AGPL 项目边界。

不做：AI、图片生成、自动发布／草稿同步、图床上传、重写 Markdown、自动改写宽表格、表格转图片、主题数量膨胀、完整 CSS 设计器、新框架或新的 Markdown 解析器。暗色阅读模拟、收藏／最近主题快捷菜单、自由颜色输入暂缓。

本轮仅授权研究与写方案。实施、修改真实库、提交、推送、打标签和发布须按后续用户请求进行；不得从本文中推导出发布授权。

后续授权补记：用户随后明确要求“完整开始更新，并且推送升级”。按本方案每阶段 BRAT 验收的停止点，本次实施并发布 P0/P1 的 `3.20.0-beta.1`，不改 Marketing 库，不替换 main／官方稳定版；用户验收后才进入 P2。

| 阶段 | 建议版本 | 本阶段结果 | 升级后应保持什么 |

## 3. 先固定现状，再改实现

2. 以 3.19.1 发行功能提交固定 19 个主题 JSON、阅读基线、背景优先级、组件样式和配方规则的指纹。不要只冻结颜色或主题 JSON。
3. 使用自己的现有 DOM／Markdown 夹具，保存无局部增强、六个配方、头尾、手工编辑文章的有序内容和规范化 HTML 基线；图片导出记录内容边界、宽高和末尾。
4. 改造测试入口使其调用真实 `TemplateManager` / presentation / canonical preparation；当前手写 `render-mobile-theme-fixture.mjs` 只能保留为演示，不能继续独立定义权威样式。
5. 建立升级执行记录 `docs/THEME_EXPERIENCE_EXECUTION.md`：阶段、任务、提交、命令结果、宿主环境、截图、用户验收、已知风险、回退点。规划阶段不填“已实现”。
6. 备份发行三文件与隔离库 data.json；真实 Marketing 库不得由测试脚本触碰。优先复用现有 `MPPreview-Refactor-Test`，不运行会清空测试库的准备脚本。

这里的基线比较允许明确列出的瞬态属性和序列化规范化差异，但不允许忽略样式、文本、节点顺序、列表层级、表格内容或图片。若发现现状缺陷，单独记录；不能通过更新黄金文件把意外变化变成“通过”。

## 4. 外观模型：版式、配色、密度、展示状态分层

### 4.1 确定每一层的所有者

| 层 | 管理内容 | 持久化与输出 |
| --- | --- | --- |
| 版式引用 | 主题 ID、主题样式修订号、来源类型 | 确认后保存，参与复制／导出 |
| 版式定义 | 标题层级、引用、列表、图片、表格、组件形态与默认节奏 | 内置版本注册表；自定义定义保持原状 |
| 配色／密度 | 当前版式的精选配色和相对节奏调整 | 确认后保存，按版式修订独立记录 |
| 现有设置 | 字体、字号、背景、局部增强、文章头尾 | 沿用现有含义，不被换色或重置微调覆盖 |
| 会话展示 | 手机 375px、自适应、专注、画廊样例、对照、滚动、搜索 | 只在当前会话，不进快照，不影响输出宽度 |

有效外观由唯一解析器生成 `ResolvedWechatAppearance`，包含完整引用、样式计划、最终配色、排版参数、背景决策及指纹。主预览、画廊当前文章、检查、复制和三种导出都接收同一解析结果，不能每个入口重新猜一次。

先还原上一轮配方附加样式，再应用版式与颜色／密度，随后应用根背景及边距的明确规则、用户选中的局部增强，最后进入现有安全规范化与输出适配器。安全规则始终保留；模板 DOM 包装必须幂等。

### 4.2 最小数据扩展

保留 `templateId` 与现有 MPSettings schemaVersion；新增独立、可选的 `wechatAppearance` 对象，内部 schemaVersion 为 1。不要把公众号外观混入 `v3` 配方元数据或笔记增强配置。

建议契约：

```ts
type BuiltinRevision = 'legacy-3.19.1' | 'reading-2026.1';
type DensityChoice = 'theme' | 'compact' | 'airy';
interface ThemeReference {
  id: string;
  kind: 'builtin' | 'custom';
  revision: string;
}
interface AppearancePreferences {
  paletteId: string; // 'original' 或该修订允许的两个替代方案
  density: DensityChoice;
}
interface WechatAppearanceSettings {
  schemaVersion: 1;
  referencesById: Record<string, ThemeReference>;
  preferencesByReference: Record<string, AppearancePreferences>; // id@revision
}
```

这些名称是建议的新接口，不是当前已有文件。P1 先实现引用与默认值；P3 才开放微调控件。外部 ThemeManifest v3 仍支持原导入／导出，不为内部偏好强制改外部 schema。

现有 ThemeManifest v3 桥接不能完整表达新六级标题、组件 roles 与版本化偏好，因此本轮不承诺新版式通过旧格式导出／导入后视觉完全一致。旧主题的 round-trip 保持原契约；导出新版时保留可表达的安全样式并明确格式限制，不能输出依赖本地注册表却无定义的文件，也不能为了“完整”偷加不受导入器支持的字段。完整新版式交换格式留待单独授权，不成为本轮稳定发布的隐性依赖。

### 4.3 兼容与样式版本

- 19 个公共 ID 不变。内置样式按 `id@revision` 解析，版本不会变成额外画廊卡片。
- 既有非空设置但没有新对象：纯读取迁移为 `legacy-3.19.1`，原模板、显示偏好、字体、背景、配方均不变；不在 load 时自动写 data.json。首次普通保存才持久化补充对象。
- 空设置／全新安装：P1 只有旧修订；P2 完成后默认采用精选新版。5 个历史主题没有新版修订。
- P2 画廊初开仍显示当前保存的修订；点击精选卡片明确试用其新版，底部显示“试用升级版／已保存旧版”。保留一个小的“使用旧版排版”入口，不重新列出 14 个重复选项。
- 升级不自动更换已选主题修订。用户显式应用新版后，仍按现有全局设置影响普通文章；本轮不新增每篇文章自动绑定外观的机制。
- 自定义主题不自动套新版视觉规则，不按颜色字符串正则全局替换。只沿用旧兼容与安全路径；未经用户选择，不能重新改写它的定义。
- 无效引用回退为同 ID 的旧修订；ID 缺失才回退默认旧修订并提示。保留原记录，不悄悄删除未知值。未知未来 schema 只读降级，不用本版默认值覆盖。
- 保留现有可见性和隐藏当前项的解析。catalogVersion 只有 P2 目录确实升级时才从当前 4 增至 5，不通过迁移让全部预设重新可见。

### 4.4 快照恢复与回退

新快照增加可选 `appearance`，记录完整引用、当前修订偏好、解析指纹与渲染修订。内置旧版本由插件不可变注册表提供；自定义主题快照还需保存深拷贝的必要定义，避免用户后续编辑自定义模板导致恢复漂移。快照不存文章副本、临时手机宽度或画廊示例。

老快照无该字段时按其主题 ID 与 3.19.1 修订解析，仍保留记录中的背景、字号、字体与配方。不得宣称可以还原 3.19.1 以前每个历史版本的完整视觉：旧记录没有这些资料。本轮承诺固定现有 3.19.1 基线，而不是凭空补回过去样式。

“重置本版式微调”仅重置当前 `id@revision` 的配色和密度；不清空快照、字体、字号、背景、配方或其他主题偏好。降级到旧插件会忽略新增字段；若用户要求精确回到升级前设置，应恢复对应备份，不以卸载删除配置作为回退手段。

## 5. 画廊：一个共享预览，安全试用

### 5.1 布局规格

默认从当前主题所属场景打开，仍提供全部、场景、自定义入口和历史小按钮。沿用现有画板图标，不增加工作台常驻按钮。

- 以画廊可用 CSS 宽高为准，不以屏幕物理分辨率为准。可用内容宽 ≥ 820px 且高 ≥ 560px：选择列约 220–260px，其余给共享预览。
- 不满足宽／高条件：选择区变为可展开的紧凑区域，默认收拢非当前项，正文预览优先；底部推荐与确认保留。不要让“选主题”与“看预览”变成互不相见的两个页面。
- 预览默认手机阅读画幅 `min(375px, 可用宽度)`，不做视觉缩放，不制造横向拖动。主工作台原有自适应／手机宽度保持原行为。
- 头部“当前文章／统一示例”与“已保存／正在试用”是临时展示选择。对照先采用同一预览区切换，不默认同时放两个手机框挤占宽度。
- 底部推荐作用允许合理换行，不永久省略关键文字。卡片名称不能被配色、用途、长描述或示例挤压；窄屏可两行完整显示，选中边框变化不能引发布局跳动。
- 320×460、375×700、600×460、900×700 都应可操作；260×360 为极限安全检查，允许压缩辅助信息，但应用／取消／切换主题必须可达。设置浮层不改变主预览的既有高度比例。
- Tab 顺序合理；卡片方向键只在卡片组获得焦点时生效，搜索框与色板不被劫持；Enter／Space 试用，确认仍是独立动作；Escape 取消未保存草稿并回到画板按钮。

### 5.2 预览来源与隔离

- 当前文章取当前真实预览的可重排 DOM 副本，包括手工编辑内容、实际文章头尾；不重建一份统计 ArticleModel 作为正文，后者按节点类别分组，并非完整有序文章。
- 统一示例使用自己的本地 Markdown 夹具，经 Obsidian MarkdownRenderer、现有转换器、同一 presentation 和输出准备处理；不手写另一份 CSS 近似结果。
- 只读展示优先用 Shadow DOM 承载生成副本，隔离 Obsidian 主题 CSS；它不进入导出 HTML。设置明确根字体与浅色文章底，避免暗色界面成为暗色文章模拟。
- Shadow DOM 还需复用现有文章基础样式片段，覆盖引用内段落、首标题等未写入内联的展示规则，不能另手写一份近似 reset。P1 同宽度下对照主预览／画廊的实际字体、段距和图宽；若隔离展示不等价，先修共享基础样式提取，不通过修改旧输出蒙混过关。
- 不搬入外部 iframe 解析器、远程字体或远程示例图片；复用已有资源状态，不为了每次点卡片重复下载图片。样例本地资源和版权来源需明确。
- 当前文章与示例切换不改变 currentFile，不把示例发往检查／复制／导出。即便在程序测试中触发输出，也必须处理真实当前文章。
- 没有当前文章时可看示例并保存全局主题；复制和导出仍保持无文章时的原行为，不复制样例。

### 5.3 外观草稿事务与异步约束

草稿包含完整 ThemeReference、偏好、当前文章标识和手工编辑修订，不只存 trialTemplateId。至少区分 `previewing / saving / applied / cancelled / closed`。

1. 打开：捕获已保存外观与当前文章基准副本。试用只更改该面板的有效外观，不写设置、快照或源文件。
2. 切换：给异步工作分配递增 generation，较旧结果不得覆盖最新主题；基准副本不被污染。连续点击只交付最后一个完整结果。
3. 对照：已保存／试用切换只控制画廊显示，不改变当前生效草稿；检查与输出使用一致的草稿引用，不能复制对照的旧版或示例文章。
4. 应用：先等待最新预览成功，再用 SettingsRepository 的串行事务只提交外观相关字段；持久化成功后才更新已保存状态并关闭。不得整体写回开窗时的 MPSettings，覆盖并发的新背景或其他设置。
5. 保存中：禁用再次应用、改选和普通取消，拦截 Escape 误关闭，并显示保存状态。saveData 不能可靠撤销，不能假装关闭窗口就取消已经提交的磁盘写入。失败保留窗口、草稿和明确错误，可重试或取消。超过 10 秒仍未完成时进入 `saving-unknown`，提示“保存仍在处理中，可关闭窗口但结果尚未确定”；允许关闭而不假报失败／取消，不触发第二次写入，原 promise 最终结果仍需收尾。未确认落盘前不创建快照、不把候选记为已应用。
6. 取消：恢复最新已保存状态并丢弃本窗口草稿，解除副本、监听器、计时器和资源引用。未保存试用须保证 data.json 字节不变。
7. 文件切换／手工内容变化：保存前使草稿失效，取消试用后以新内容重新打开；不将旧文章异步结果挂到新文章。已开始的持久化按实际成功／失败收尾，不伪称取消成功。
8. 其他面板修改全局外观：检测冲突、使草稿失效并恢复最新保存状态，不恢复成最初旧状态；其他不相关设置按最新值合并。至少两个面板覆盖测试。
9. 锁定预览：按锁定的文章上下文取副本，不因活动编辑器切换误换文章。进入内容编辑模式前取消试用或明确应用，不能强迫保存草稿。试用期间的保存快照先要求确认应用，不能用已保存 ID 记录正在显示的未保存外观。

滚动以可重排基准文章的稳定块标识／标题及出现序号加局部偏移保存；失败才回退比例。不要使用按类型分组的 ArticleModel.node ID 当文档位置。异步图片完成后只校正当前 generation 的锚点，不把用户后续滚动强行拉回。

## 6. 版式升级：先拆开视觉规则与安全规则

### 6.1 公共安全层

所有修订都保留安全过滤、宽度限制、长词换行、代码换行、图片等比缩放、内容顺序与阻断检查。新阅读规则不能把安全目标误当成统一视觉：不再强写全部列表行高、引用行高、图片间距、标题对齐和组件圆角。

新修订由版式定义提供所有可阅读默认值，缺失字段才落到保守默认。h1–h6 都有明确层级，h4–h6 不再只共用一个视觉定义；旧结构未声明这些字段时走兼容分支，不能改坏用户自定义主题。主题图片、表格和代码字号不被后续“基线”抹掉，正文仍继承用户字号。

正文默认节奏先保持现有三档：紧凑 1.72 / 0.85em，标准 1.78 / 0.95em，舒展 1.82 / 1.05em；这是新版式的初始设计参数，非所有节点的统一值。标题前距大于后距，列表有独立项间距，引用内部首尾不重复叠加段距，图片与图注按一组处理。

### 6.2 根背景与边距的确定优先级

当前 container 未进入真实样式计划，背景模块又覆盖根 style；P2 不得只修改 JSON 来声称完成纸感和留白。

- 旧修订／自定义主题维持现行背景路径及固定基础留白。
- 新修订用根样式合成器一次输出：默认背景 ID 时采用主题定义的根底色；显式其他背景时采用用户背景。没有擅自改写 backgroundId。
- 根留白由新主题 tokens 负责，初始左右 18–20px、上下 16px；不依赖手机模式临时变化，不在背景模块重复加 padding。用户自定义背景非零留白如何保留需列入基线测试，不能无声删除。
- 主题默认色与用户背景叠加后再检测文字对比度。简单颜色可计算；复杂图片／渐变／透明组合无法证明时提示风险，不擅自改背景、不宣布对比度通过。
- 模式切换不改文章 style；相同外观、文章和导出面板下，自适应／375px／专注切换的输出 HTML 与导出宽度必须相等。

名称与 ID 均保持；以下是独立实现方向，不复制上游模板。每对至少在标题、引用、列表、图片／信息块中有三项可见结构差异；不能靠颜色或 1px 装饰充数。

### 6.4 局部增强与组件

配方继续叫“局部排版增强”，留在更多工具；不自动按场景改配方、不改六个 ID、不取消已有稿件效果。配方显式选择的局部结构优先于版式该元素默认形态，并在画廊底部以短提示显示当前增强，避免误判主题差异。

版式比较的标准样例默认关闭增强；真实文章预览保留当前增强，不能为了“更好看”临时关闭用户设置。重复应用、A→B→A、换色、恢复快照均须先还原配方基础样式，步骤标签不重复，不跨有序列表偷偷重编号。

组件的新修订使用明确角色 tokens：标题、正文、边线、浅底、提示、语义状态；替代依靠原始十六进制颜色猜用途的方式。只对自己生成的组件改造；成功／警告／失败等语义颜色保留。普通 Markdown 表格保持结构，只报告窄屏风险，不自动移列、截短内容或改成卡片。

## 7. 框架内配色与密度：P3 才开放

- 每个新版式恰好三个精选配色：原生 + 两个备选。使用“墨黑、松绿、海蓝”等有意义的名称与小色点；不以经典、优雅等模糊词制造新的主题名。
- 每个主题给出允许的 paletteId 列表，不能把 14×3 个组合平铺到主画廊，也不在卡片里塞色板。
- 颜色角色独立：正文、次要文字、强调文字、装饰强调、底色、边线、强调底上的文字。正文不整篇染成品牌色；两种备选不改变标题结构或列表布局。
- 颜色调整不得全局正则替换 CSS。旧修订和没有角色映射的自定义主题不开放自动换色；用户仍可沿用原主题或显式试用新版。
- 保留并扩展现有对比度保护，对实际背景、标题、链接、引用、表格、图注、代码注释和信息块文字检查。新版普通文字要求不低于 4.5:1；此项目门槛不等于完整 WCAG 认证。
- 密度只有“跟随主题／更紧凑／更舒展”。初始间距倍率 1 / 0.90 / 1.12，正文行高倍率 1 / 0.96 / 1.04，并限制最终正文行高在 1.65–1.95。以最终视觉验收调优并记录，不假称这些数值是上游或微信的标准。
- 倍率只作用于版式声明可缩放的垂直距离；不改字号、页面宽度、水平缩进、图片比例、表格列、代码缩进或任务列表标记。标题前后、图注和引用内部比例保持。
- 新配色／密度按 id@revision 记忆，仅确认保存；试用和重置都参与完整草稿事务。换主题不把 A 的密度或颜色带给 B；回到 A 恢复 A 的保存偏好。
- 不增加自由 HEX 输入、首行缩进开关、左右留白滑杆、代码样式大全。少量微调放在画廊预览附近的折叠区域，不把工作台重新排成多行。

普通文章块目标横向溢出 ≤ 1 CSS px，正文和控件无不可访问截断；宽表格单独记录，不截掉内容。新精选主题普通文字颜色与实际底色比 ≥ 4.5:1。旧修订、自定义复杂背景的已知风险单列，不能为了零风险报告改变它们。

### 9.4 “结构不同”不能只靠字符串或哈希

保留旧的 CSS 去色检查作为辅助；新增同一文章的实际布局数据与灰阶截图。按 h2/h3、引用、列表、图片／信息块分别记录几何与装饰特征。

每场景两套至少三个类别有实质区别：例如引用从浅底边线变为无底横线、列表从卡片变为原生序号、章节从侧锚变为开放层级；间距区别需达到约 15% 才可作为一项证据，单独换色、细微边框或哈希不同不计。

人工复查 375px 同文灰阶对照：不看主题名称仍能描述两者阅读结构差异；并核对完整彩色文章的连续阅读，而不是只看 h2 截图。人工意见记录为设计判断，不包装成未经实施的盲测或用户研究。

## 10. 发布与可靠回溯

候选先在独立 beta 分支／精确 beta 标签发布给 BRAT，默认主分支 manifest 保持上一稳定数字版本。beta 元数据与官方稳定版契约分开；不修改官方检查让它接受 prerelease，也不让官方用户误拉候选。

经用户明确发布授权后：同步 package、manifest、versions；裸数字标签精确匹配 manifest.version；原有 CI 构建并执行质量门槛；保留旧标签与资产。三个安装资产为 main.js、manifest.json、styles.css，许可证／NOTICE 等继续按现有发行规则附带。

稳定提升须比较最终验收 beta 与稳定构建的 JS／CSS：理应只有版本和发布记录变更；若包含版本常量导致字节变化，说明具体差异并重新检查，不能谎称字节相同。

下载发行资产验证版本、插件 ID、大小／哈希；官方目录扫描／展示当前版本和应用内安装分别核对。GitHub 成功不能直接宣称官方更新成功。依据 [官方目录管理说明](https://docs.obsidian.md/community-directory/manage-entry)，留存扫描结果，不重复做首次上架提交。

失败回退：

1. 停止后续阶段，冻结失败候选与证据；恢复上一通过版本的发行文件。
2. 不删除 data.json、不卸载清配置、不改 Markdown。新版本内可先选回旧版样式修订。
3. 二进制降级后新字段被忽略；精确恢复升级前全局选择时再由用户确认恢复备份，先保存当前 data.json 和新增快照。
4. 已正式发布的坏版本通过新的修复版本解决，必要时说明固定前一版的办法；不删除旧发布、覆盖既有标签或伪造历史。
